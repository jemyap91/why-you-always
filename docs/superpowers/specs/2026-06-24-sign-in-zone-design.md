# Sign-in zone for session marking — design

**Date:** 2026-06-24
**Status:** Approved (pre-implementation)

## Problem

Gesture-based session marking keeps switching/ending by accident. Even after
restricting gestures to hands *outside* the sink zone, the bar is still "any
out-of-sink hand that looks like 1 or 2 fingers for ~1s." During washing the
non-washing hand, the lifted washing hand, and reaching motions constantly form
incidental `1`/`2` shapes, and the toggle rule means a single misread flips the
session. It is too fragile.

## Goal

Make marking a session **deliberate and hard to trigger by accident**: gestures
are recognized **only when a hand is inside a small dedicated "sign-in" zone** —
a box placed in a corner, away from the sink and normal hand paths. Everywhere
else, finger poses are ignored entirely.

## Approach

Add a second calibrated zone, `sign_in_zone`. The engine recognizes a gesture
only from a hand whose centroid is inside that zone; the existing
`SessionController` toggle semantics are unchanged (hold `1`/`2` ~`gesture_hold`
seconds to start, repeat to end, other number to switch). This replaces the
current "ignore hands inside the sink" filter with the stricter "only accept
hands inside the sign-in zone."

## Components

### `config.py` (changed)
- Add `sign_in_zone: Zone` to `Config` (required). This is a **breaking config
  change**: an existing `config.yaml` without `sign_in_zone` will fail to load
  and must be regenerated by re-running `calibrate`.
- `Thresholds` unchanged.

### `calibrate.py` (changed)
- After dragging the sink zone, drag a second box — the **sign-in zone** —
  prompted as "drag the sign-in box (a corner away from the sink)". Save it in
  the `Config`.

### `engine.py` (changed)
- `_resolve_gesture(hands)`: return the first gesture (`one`/`two`) from a hand
  whose centroid is inside `self._config.sign_in_zone`; ignore all other hands.
  (Replaces the "skip hands inside the sink" logic.)
- `annotate(...)`: also draw the `sign_in_zone` rectangle in a distinct color
  (cyan) with a "sign in" label, so the user can see where to hold their hand.
  Signature unchanged — it reads `config.sign_in_zone`.

### Unchanged
`SessionController` (toggle), `WashCycleEngine`, `gesture.py`, the store, the
dashboard.

## Data flow

`hands → _resolve_gesture (sign-in-zone only) → SessionController → active washer
→ WashCycleEngine → store`. Only the sign-in zone gates which hands can change
the session; the sink zone still gates wash counting (unchanged).

## Edge cases

- **Sign-in zone overlapping the sink or the carry-out path:** would reintroduce
  false triggers. Placement is the user's responsibility; calibration prompt and
  README call this out. Not enforced in code.
- **No hand in the sign-in zone:** `_resolve_gesture` returns `"other"`; the
  session is unchanged.
- **Washing hand:** it is in the sink, not the sign-in zone, so it cannot affect
  the session.

## Testing

All detection behind dependency-injected fakes; no models in tests.

- `_resolve_gesture`: a `one`/`two` hand **inside** the sign-in zone resolves to
  that gesture; the same gesture **outside** the sign-in zone resolves to
  `"other"`; a hand in the sink (and not the sign-in zone) is ignored.
- engine e2e: a gesture made inside the sign-in zone starts a session and a
  subsequent in-sink wash counts for that person; the same gesture made outside
  the sign-in zone never starts a session (so the wash is uncounted).
- `config`/`conftest`/`test_annotate`: `Config` now requires `sign_in_zone`;
  fixtures provide one placed away from the sink zone.
- `calibrate`: source still references no skin/drying; now references the
  sign-in box.

## Out of scope

- Dashboard buttons for marking (the sign-in zone was chosen instead).
- The parked reset button.
- Auto-placing the sign-in zone (it is calibrated explicitly).
